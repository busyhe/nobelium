# 优化实施与验证

## 实施范围

- 内容边界：列表使用统一的 `PostSummary`；摄影详情只返回摘要和照片列表，正文页面保留 recordMap。分类、计数与路由共用一套规则；默认 Journal 使用 `~journal`，避免与同名真实标签混淆。
- 服务端：按 TTL 和 LRU 管理缓存，同一资源的并发请求合并；失败结果不缓存。构建进程共享一次内容索引快照，两个静态生成 worker 限制上游并发；临时快照在构建结束后删除。
- 照片墙：12 个分区复用 120 个按钮，逻辑分类可以无限循环。首屏 HTML 只渲染中心行照片，其他附近图片在 hydration 后加载。保留已有布局、动画参数和 WebGL 着色器。
- 渲染资源：绘制循环按需启动，静止与后台时停止；WebGL 延后加载，减少动态效果模式直接使用 DOM 图片。纹理按条目与像素预算回收，保护正在显示的图片。
- 浏览体验：恢复照片墙位置和模式；搜索词写入 URL；详情提供前后翻页、照片序号链接、图片失败重试；缩略图仅加载选中位置附近的图片，并预取相邻大图。来自索引的关闭动作返回历史来源，直接打开则替换为首页。
- 路由反馈：非 shallow 跳转显示加载状态；失败提供重试；保存并恢复索引滚动和焦点。冷路径 404 带重新验证时间。
- 正文：动态组件在模块顶层声明；文档样式使用 CSS Module，代码和公式资源按需加载。使用 react-notion-x 8 支持的原生 toggle，修复旧 `toggle_nobelium` 类型导致内容消失的问题；根 collection 类型转换不修改共享缓存。
- SEO 与持续检查：canonical、分享封面、完整 sitemap；图片详情不加载正文资源或正文预加载字体。新增离线测试、CI 和构建体积预算。Web Vitals 复用已有的 GA 配置，不新增分析服务。

| 首页 HTML（原始字节） | 501,737 | 114,514 |

本次最终构建生成 78 个静态页面，耗时 18.8 秒，无路由超时重试。首页 gzip HTML 为 12,850 字节；sitemap 合计 126 个不同地址。所有构建预算检查通过。

## 自动检查

```sh
pnpm lint
pnpm test
pnpm build
```

`pnpm test` 包括 17 项：分类碰撞和去重、DTO 数据隔离、Notion 缓存不可变、原生折叠块实际 SSR、URL 编码与 canonical、窗口正反向循环、固定 DOM 槽位、图片序号边界、纹理释放、绘制循环休眠、TTL/LRU、并发请求合并、失败重试、构建快照和请求间隔/并发。

`pnpm build` 使用真实 Notion 数据。postbuild 生成 sitemap 后执行 `pnpm check:build`，要求：

- 首页最多 120 个照片按钮，HTML 小于 200 KiB，初始 CSS 小于 64 KiB。
- 预渲染摄影详情 JSON 小于 128 KiB，且不包含 recordMap。
- 首页没有正文预加载字体。
- sitemap 覆盖所有已发布作品，编码前后等价的路径没有重复。

CI 的 Quality 工作流运行 lint 和离线测试；真实内容构建仍需要可访问的 Notion 环境。

## 测量边界

体积数据来自本地生产构建；耗时受 Notion 网络与缓存影响，不是线上性能承诺。没有收集线上 LCP、INP、CLS 分布或真实用户 GPU 内存数据。纹理像素预算允许当前可见图片暂时超过上限，以免销毁正在显示的纹理。

sitemap 使用当前构建的完整已发布索引，新发布作品的 sitemap 条目在下次构建更新；页面内容仍保留 ISR。浏览器拒绝 sessionStorage 时使用普通导航。上游 Notion 图片超时仍可能发生，界面提供占位和重试。

Next.js 的动态导入要求组件在模块顶层声明，参见[官方说明](https://nextjs.org/docs/pages/guides/lazy-loading)。
